## What's been done this "chapter" of work

1. Discovered this worktree/branch didn't have the WSL2 dev-setup work at
   all (it branched off `main` before those commits existed); fast-forward
   merged `claude/local-origin-upstream-diff-902ea8` into it to pick it up
   (zero conflicts - this branch's HEAD was a strict ancestor).
2. Ran `wsl_start_ragflow.sh` from this worktree's path; base services were
   already up from a prior session/boot, backend started cleanly.
3. Diagnosed the Vite dev server silently dying seconds after the script
   reported it started (plain `nohup ... & disown` didn't survive the
   invoking `wsl -e bash -lc "..."` session exiting, unlike the Python
   backend processes started the identical way). Manually relaunched with
   `setsid` and confirmed it now survives across separate WSL invocations.
   **Root-caused but not yet folded into the script** - see
   `wsl_dev_README.md`'s new gotcha entry.
4. Diagnosed the long-standing `RAGFlow version: unknown` cosmetic issue:
   Linux git inside WSL2 can't resolve this worktree's Windows-style
   `gitdir:` path in `.git`, so `get_ragflow_version()`'s `git describe`
   fallback throws and is swallowed. Confirmed Windows `git.exe` (reachable
   via WSL2 interop) resolves the same path fine.
5. Fixed it properly: `wsl_start_ragflow.sh` now has a new step 2 that
   regenerates a `VERSION` file at repo root every run via `git.exe`,
   mirroring exactly how the official Dockerfile bakes in `VERSION` at
   image build time. Verified the already-running backend picked it up
   live (no restart needed - `get_ragflow_version()` only caches once it
   reads a non-`"unknown"` value) via `curl .../api/v1/system/version`.
6. Updated `wsl_dev_README.md`'s gotchas section to reflect both fixes/
   findings above (version fix confirmed working; frontend-detach issue
   documented with a manual workaround, not yet scripted).
